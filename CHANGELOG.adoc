== v0.1.8 — 2026-07-16

=== Fixed

* **Filigrane invisible sur la plupart des PDFs sources.** Bug
  reproduit sur un RIB Caisse d'Épargne : `watermark rib.pdf
  -t "..." -s tiled` retournait « Filigrane appliqué » avec
  code 0 mais le PDF de sortie était visuellement identique à
  l'entrée.
+
Cause : le stream du filigrane référençait `/Helvetica` (fonte
Type1 standard) alors que les `/Resources /Font` de la page
héritaient d'autres fontes (ex. Ubuntu-Light, Ubuntu-Medium,
Calibri sur le RIB testé). Tout viewer PDF **skip silencieusement**
les opérateurs `Tj` qui suivent un `Tf` référençant une fonte
inconnue, résultat : rien ne se rend, aucune erreur.
+
Fix : `ensure_helvetica_declared(page)` injecte
`/Helvetica -> {Type: Font, Subtype: Type1, BaseFont: Helvetica,
Encoding: WinAnsiEncoding}` dans les Resources de chaque page
avant l'ajout du stream.

* **Style `tiled` peu dense.** Ancienne implémentation posait 7
  occurrences le long d'UNE SEULE diagonale (spacing_x calculé
  avec la longueur totale du texte + filtre de bornes trop
  agressif après rotation par-Tm). Une page A4 avec un texte de
  73 caractères et taille 28 pt donnait 7 tuiles au lieu de
  ~90.
+
Fix : refactor complet du builder tiled. La rotation est
maintenant appliquée **globalement** via un opérateur `cm`
autour du centre de la page (une seule matrice), et la grille
de répétitions est **rectiligne** dans le repère pré-rotation
(plus simple à raisonner, garantit densité uniforme).
+
Grille dimensionnée sur la diagonale de la page pour couvrir
tous les coins post-rotation. Résultat sur le même RIB A4 :
96 tuiles au lieu de 7.

=== Changed

* **Vraie transparence via `/ExtGState /ca`** au lieu du
  blanchissement de couleur historique (mixage avec blanc du
  fond). L'ancien schéma rendait le filigrane invisible sur un
  fond noir ou coloré, et très pâle sur fond blanc à faible
  opacité. Le nouveau utilise l'attribut `/ca` (non-stroking
  alpha, PDF 1.4+) et `/CA` (stroking), déclarés dans
  `/Resources /ExtGState /GS_watermark` de chaque page.
+
Compatible avec tous les viewers modernes. `--opacity 0.15`
donne désormais un rendu identique quel que soit le fond.

* **Banner CLI et `--version`** corrigés : `crystal-watermark`
  → `watermark`. Le binaire s'appelle `watermark` depuis le
  début (cf. `feedback_shard_naming.md` : créations ALOLI sans
  préfixe `crystal-`). Le banner mentait.

== v0.1.7 — 2026-06-23

=== Added

* **Flag `-R` / `--rasterize`** sur le CLI. Après l'application du
  filigrane, post-traite le PDF de sortie via
  `crystal-combine-pdf rasterize` (chaque page devient un JPEG
  plein page). Conséquence : le filigrane devient **indissociable
  du contenu**, impossible à retirer sans détruire les chiffres
  utiles (IBAN, montants, signatures). Pattern observé chez
  DossierFacile pour les RIB protégés.
+
[source,bash]
----
crystal-watermark rib.pdf -t "Document destiné à X - 23/06/2026" \
                          -s tiled --rasterize
----
+
Le résultat n'a plus de texte extractible (`pdftotext` rend
vide), plus aucune police embarquée, le filigrane et le contenu
fusionnés en un JPEG par page.
+
Flags associés (réglent la qualité de la rastérisation) :
+
* `--rasterize-dpi N` — résolution de rendu (défaut 200 dpi).
* `--rasterize-quality Q` — qualité JPEG 0-100 (défaut 85).

=== Requirements

* `crystal-combine-pdf` 1.0.31.44+ dans le PATH (qui fait
  lui-même le shell-out à Ghostscript). Erreur explicite avec
  pointeur d'installation si absent.

== v0.1.6 — 2026-06-05

=== Added

* **Callable CLI entry point `Watermark::Cli.run(argv) : Int32`**
  (`src/watermark/cli.cr`). The command logic moved out of the top-level
  `src/cli.cr` script into a method, so it can run both as the standalone
  `watermark` binary AND in-process from the unified `alolipdf` binary
  (aloli-crystal/pdf-tools). Behaviour is unchanged — 24 specs green.

== v0.1.5 — 2026-06-05

=== Changed

* **Aligned on `pdf ~> 1.6`** (was `~> 0.3`). Part of levelling the whole
  ALOLI PDF suite onto a single `pdf` major so the tools can be built
  together (e.g. under the unified `alolipdf` binary). watermark only
  uses `PDF::Reader`, which is unchanged — no code change, 24 specs green
  against pdf 1.6.0.

== v0.1.1 — 2026-04-25

Tightens the integration test suite now that `pdf` v0.3.4
fixes the byte-vs-char offset bug in `find_xref_offset`.

* Integration specs now drive their assertions through the real
  `PDF::Reader.open(dst)` (page count + per-page MediaBox) instead

  byte-identical between v0.1.0 and v0.1.1.

== v0.1.0 — 2026-04-25

First public release. Pure-Crystal text watermarking on PDF and image
files, designed to mark identity documents and confidential files
before transmission. Inspired by the use case behind
https://filigrane.beta.gouv.fr/[filigrane.beta.gouv.fr].

* **PDF watermarking** via pdf's `PDF::Reader.add_content_stream`:
  injects a watermark content stream on every page, preserving the
  original page content. Supports any page format (A4, Letter, A3, …)
  by reading the actual `MediaBox` of each page.
* **Image watermarking** for PNG and JPEG inputs (always written back
  as PNG): a bitmap font is rendered pixel-by-pixel with the requested
  opacity into the source image.
* **Five styles**: `Diagonal` (auto-sized to the page diagonal,
  default), `Tiled` (grid of repeated watermarks), `Header`, `Footer`,
  `Center`.
* **CLI** at `bin/crystal-watermark` with short and long flags for
  every option (`-t`, `-o`, `-s`, `--opacity`, `--color`,
  `--font-size`, `--rotation`, `-v`, `-h`).
* **API**: `CrystalWatermark.apply(input, output, text, style, options)`
  auto-dispatches based on file extension.
* **WinAnsiEncoding mapping** for French/German/Spanish accents and
  common typographic punctuation (em-dash, smart quotes, …).
* Bilingual README (EN + FR) and CHANGELOG.
* CI: ameba lint + crystal spec on every push.
* **19 unit tests** covering options, image watermarking (5 styles,
  pixel-modification check, accents, error paths) and the public API.
